# Bounded read-only DSI counter probes

Step15 reads timing and INTF_FRAME_LINE_COUNT_EN on both saved enuma DSI blocks (0x0ae6b800 and 0x0ae6c000), four reads total. Eligibility requires nonzero timing and both low enable bits set, matching the fixed Qualcomm SDE setup value 0x3. It never enables counters or reads a disabled counter.

Step16 obtains the same eligibility, reads eligible INTF_FRAME_COUNT values at +0xac, calls the existing gBS Stall once for 100000us, reads those frame counters again, and checks the original timing/enable words are unchanged. It performs at most twelve MMIO reads and one wait. Success requires at least one modulo-UINT32 frame delta in 1..64, with no eligible interface showing a larger delta. Zero delta, disabled counters, changed configuration, wait errors/warnings or excessive deltas return a negative/unknown predicate; they are not proof of an inactive display. A reset coincident with wrap can mimic a small modulo delta. Samples are not atomic and do not establish SSPP routing, memory ownership, physical/IOVA identity or visible pixels.

The 100ms request is an observation window, not a measured display-rate claim or a watchdog. A hung register read or Stall can prevent the existing synchronous Core fallback. The companion qualifies the code with fake-MMIO/wait boundary tests, actual AArch64 objects, unchanged generated dependencies, actual FD packaging and matching control/positive/complementary builds before temporary hardware trials. No new library, constructor, allocation, mapping, pixel access, register store or verification flag is introduced. R-005 remains consumed.
