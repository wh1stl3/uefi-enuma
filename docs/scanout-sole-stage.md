# Isolated sole-stage probe after step22 timeout

Step22 forward did not return within75s and required manual recovery; reverse is frozen and unexecuted. Do not repeat that image. Step23 removes every new LM_OP_MODE/blend/alpha read and encoding wait. It starts from the byte-identical step20 algorithm, adds only a local four-word decode using EnumaBlendSingleStage after masking known CTL_LAYER border bit24, and retains full original words for stability checks. It never selects a later source/CTL/LM. At most250 MMIO reads, at most two existing Stall(100000), no pixels/MMIO writes, mappings, allocations or new dependencies. Only the isolated sole-source staging predicate is added; dim/alpha are intentionally unclassified, not presumed good.

Fixed Xiaomi52a2f18 CTL setup_blendstage can set CTL_MIXER_BORDER_OUT when no BASE source is configured, so border alone is not another SSPP. Rejection still means other/unknown/unsupported staging or inherited step20 gate/stability refusal; it does not prove actual occlusion. Passing does not prove no dim, valid alpha, physical LM/pingpong/DSC routing, fetch or visibility. Step22 failure's root cause is not yet established: longStall and fuller sampling remain isolated differences. This new candidate follows manual recovery and independent Android/root/slot/unlock/partition verification, not a retry of the failed image.
