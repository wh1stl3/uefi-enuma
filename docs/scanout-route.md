# Stable staged-source / selected-interface progress association

Step19 restricts hardware major/minor to 6.0, then selects exactly the first bounded descriptor used by historical step12/R-005 selection. Saved enuma FDT provides CTL offsets 0x2000..0x2a00, not other devices' 0x1000 offsets. DSI interfaces are 1/2, bits 1/2 in CTL_INTF_ACTIVE(+0xf4). It scans six CTLs and each CTL's six LM layer words, including LM5's special 0x24 offset. Nonvirtual VIG0..3/DMA0..3 stage fields match pinned Xiaomi 52a2f18 sde_hw_ctl.c. It never substitutes a later descriptor merely to make a route predicate succeed.

The first CTL/LM that stages this source and selects an actually active DSI is retained. That SAME selected DSI must advance by 1..64 without wrap in EACH of two existing Stall(100000) windows. Its active bit stays set; timing/enable, chosen CTL interface mask, all four chosen LM staging words, all six descriptor words and final hardware version stay unchanged. At most 241 MMIO reads and two waits; early refusals read less. No new library, constructor, allocation, mapping, framebuffer access or MMIO write. Historical source contracts and consumed R-005 authorization stay unchanged.

This proves only a stable configuration association plus counter progress if its predicate passes. CTL/LM registers may be stale/shadow state; a selected interface does not prove that particular LM is actually supplying its pixels. No mixer-output/pingpong/DSC/fetch-success/visibility/alpha/occlusion/physical-IOVA claim follows. Failure can mean no descriptor, wrong version, no active selection, no nonvirtual staging, changing state, wait issue or no bounded progression. Complementary runtime timing is indirect predicate evidence, not a numeric dump. Neither pass nor failure alone settles the black-screen root cause.
